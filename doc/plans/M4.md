# M4: couches sols (CSW → JSON validé → carte)

## Objectif
1. `apps/explorer-les-cartes/scripts/build-sols-layers.ts` (`bun run build:sols-layers`) : CSW `gissol-osf_c` → 7 fiches
   (identifiant, titre, résumé, organisation, liens `OGC:WMS|OGC:WMTS|OGC:WFS|TMS`) → validation de chaque nom contre les
   capacités (wms-v, wms-r, WMTS, WFS, TMS) → `src/data/sols-layers.json` (trié, sans horodatage, rejets avec motif) + résumé.
2. Panneau DSFR « Données sols » : fiches (titre, extrait du résumé, organisation, services en badges), « Ajouter à la carte »
   (WMTS en EPSG:3857, sinon WMS raster, sinon WMS vecteur), « Retirer de la carte » ; état dans le store ; couche visible dans le
   gestionnaire de couches avec son titre.
3. Lien profond `?layer=&type=&url=` (contrat C4, `geonetwork-ui.md` §10) : correspondance avec le JSON, sinon capacités en direct
   (TanStack Query), sinon alerte « Couche introuvable » ; TMS (style MapLibre) : avis « format non pris en charge ».

## Choix
- Analyse XML avec `@xmldom/xmldom` (script Bun et tests) ; types du fichier JSON et garde d'exécution partagés (`src/data/solsLayersSchema.ts`).
- TMS validé contre la racine du service `https://data.geopf.fr/tms/1.0.0` (TileMapService) : l'annexe `gpf-rok4-server-wmts-tms`
  ne liste aucune couche vecteur (question M-3).
- WMTS `INRAE_CARTE-SOLS` publié seulement en EPSG:2154 : préférer le WMS raster pour « Ajouter » ; le lien profond WMTS reprojette
  via le module CRS de geopf-ext si possible, sinon repli WMS (à vérifier).

## Tests
Vitest : analyseur CSW (extrait de fixture), validateur (capacités simulées), cohérence du JSON commité avec le schéma, store,
panneau (clavier), lecteur de lien profond (connu, inconnu validé en direct, introuvable, TMS). Playwright (port 8101) : ajout d'une
couche sols (GetMap/GetTile 200, présente dans le gestionnaire), liens profonds WMS et WMTS ; captures `doc/screenshots/M4/`.
